# Intent: add an "Ask Zero State" Q&A assistant

## Problem

Visitors can browse the portfolio but cannot ask a question about the company or a
project and get a direct answer. Collaborator Badri Rajendran's site
(`badri-rajendran.github.io`, linked from `collaborators.html` as "Ask Badri.ai")
has an assistant that answers questions about his work. Danny wants the same for
Zero State.

## Proposed outcome

A small chat widget on zer0state.com that answers questions about Zero State, its
products, client work, community work, and skills. It answers only from an approved
knowledge file built from pages already on this site.

- **Frontend (this repo):** one script and one stylesheet under `assets/`, loaded by
  shared pages. It shows a launcher button, a floating panel on desktop, and a
  full-screen sheet on phones. It uses `tokens.css` colors and type. It renders model
  output as text, never as HTML. If no endpoint is configured it renders nothing.
- **Knowledge file:** generated by a script from existing page copy and
  `site-manifest.json`, so answers cannot go beyond what the site already says.
  Product status keeps its evidence label (`LIVE`, `NOT_READY`, and so on).
- **Backend (not deployed by agents):** a Cloudflare Worker that sends the knowledge
  file as a cached system prompt to a Workers AI model, streams the reply, and enforces
  origin checks, message size limits, and a rate limit. Source can live in `workers/ask/` here or in its own repo (open question).

Out of scope: voice, accounts, stored chat logs, pricing or quote answers, booking,
changes to the existing gated `/chat/` GLM preview, and any production deploy.

## Affected users / systems

Site visitors; `assets/` (new widget files); shared page templates that load
`site.js`; `scripts/validate-site.js` (new assets and links must pass);
`site-manifest.json` (knowledge source); a new Cloudflare Worker and its secret.

## Constraints / non-goals

- Site/brand scope only. The assistant must not invent products, availability,
  prices, dates, legal or licensing claims. It says "I don't know" and points to
  `zer0state@zer0state.com` instead.
- No secrets in the tree. Workers AI needs no API key.
- No production deploy, DNS change, or spend without a human yes.
- Respect `prefers-reduced-motion`; no change to the mark or highway-centerline motion.
- Answers about collaborators come only from approved `collaborators.html` copy.

## Decisions (Danny, 2026-10-31)

- Hosted, not local: a Cloudflare Worker. The GLM cluster is not used for this.
- Cheapest model that works, through the Worker: DeepSeek V4.1 Flash on Workers AI,
  reasoning off. No third-party API key; about $0.0005 per answer with the cached
  knowledge prefix. Supersedes the earlier Claude Haiku choice.
- Spending is watched with a Cloudflare usage alert; the Worker limits each visitor IP
  to about 6 questions a minute.
- Cover every project listed on the site; give no private or proprietary information.
  Enforced by `npm test` (coverage and private-data checks) and the assistant's rules.
- Worker source lives in `workers/ask/` in this repo; a human deploys it.
- Widget on every shared page, closed until clicked.
- One-line notice under the input that answers are AI-generated, linked to
  `privacy.html`.
